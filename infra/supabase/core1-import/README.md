# Core 1 database

Apply the reviewed migrations in order: `20261114125704_foundation.sql`, `20261114130240_core1_security_workflows.sql`, `20261114131827_signed_timeline.sql`, then `20261114141830_checkpoint_media_metadata.sql`. These filenames match the recorded hosted migration versions. Later phase migrations remain unapproved until independently reviewed and tested. Seed is explicit and synthetic; do not apply a destructive database reset to a hosted project.

`tests/core1_security.sql` is a transaction that rolls back all fixtures. Run as database owner using a SQL connection or Supabase execute_sql. It checks child family boundaries, parent own status/voice, circle assignment-only access, revoked membership, private content, mutation denial, cross-tenant foreign keys, duplicate ingestion, stale leases and atomic workflow dispatch. A migration is not verified until this SQL runs successfully against PostgreSQL.

All writes go through the backend and Cedar. No client can create memberships, modify permissions, acknowledge emergencies, or change signed audit events. Children read safe operational tables in their family. Parents read their own call status and voice-post metadata. Circle members read their assigned task metadata only. Transcripts, voice object paths, raw events, timeline human lines and encrypted contacts have no client grant. Authorization membership helpers live in a private schema and resolve the current authenticated user against live server-managed memberships. Public service-only metadata RPCs are narrow bridges into private storage metadata and cannot be executed by browser roles. Never use user-editable JWT metadata as an authorization source.

Media buckets `sahaj-voice`, `sahaj-recordings`, and `sahaj-lines` are private with no direct client access. Backend upload/link handlers must verify participant, unrevoked purpose-specific consent, family path, expiry and permission before creating a signed URL (maximum 60 seconds). Database rows store ciphertext/object paths; encryption keys remain outside PostgreSQL. The expiry columns are not a deletion service: retention cleanup and key rotation must be configured before real data.

Ingestion RPC `ingest_raw_event(p_source,p_provider_event_id,p_event_type,p_family_id,p_metadata,p_payload_hash,p_payload_ciphertext)` is service-only. Metadata must be a redacted server allowlist; hash is SHA-256 over the exact stored JSON envelope including the resolved person binding. Provider signatures are verified separately over original request bytes before parsing. Same provider ID with a changed hash, type or family fails with SQLSTATE 23505. Never resolve unknown identities from caller-supplied family IDs. Query `provider_identities` by source/account/HMAC identifier and approved binding; reject disabled/revoked/mismatched agent, deployment or attempt.

`claim_raw_events` uses `FOR UPDATE SKIP LOCKED`, bounded attempts and UUID lease tokens. Finish requires the token and an unexpired lease. `dispatch_raw_event` inserts a durable workflow job and acknowledges ingestion in the same transaction; use this instead of finishing before work is durable. Processing is at least once; provider actions must use the outbox `dedupe_key` as provider idempotency key. An expired outbound lease becomes `delivery_unknown` and is never reclaimed automatically. Workers must also finish with error code `delivery_unknown` for timeouts or uncertain responses. Use `reconcile_outbox` with processed same-family verified provider evidence and outcome `delivered` or `confirmed_not_sent` before changing that state. Ordinary `failed` is only for a confirmed pre-dispatch failure. `claim_outbox`/`finish_outbox` use the same lease tokens. Error fields accept short codes, never exception text or personal information. A dead event is an operator-visible failure, not successful handling.

Reconciliation evidence is bound to `metadata.outbox_id`, `metadata.outcome`, and event type `delivery.confirmed` for `delivered` or `delivery.not_sent` for `confirmed_not_sent`. An unrelated same-family event cannot authorize reconciliation. The verified provider status lookup must write these fields; until it exists, unknown deliveries remain blocked.

`claim_workflow_jobs`/`finish_workflow_job` lease workflow execution. An interrupted finish requires a durable checkpoint reference and interrupt reference; interrupted jobs are not claimed. After checking the caller and Cedar, `resume_workflow_job(job_id,family_id,expected_interrupt_ref,resume_payload_ciphertext)` atomically consumes the pending interrupt once and persists encrypted resume input for the claiming worker. The fourth parameter is optional; it must never contain plaintext. Finishing the continuation clears that input. Persist actual LangGraph checkpoints before referencing them. Never perform external side effects inside a retried workflow node; enqueue an outbox command instead.

Workflow job/checkpoint orchestration, purpose-specific consent validation and action-state transitions are backend responsibilities. Database references enforce tenant integrity but do not replace Cedar or verified provider acceptance. Do not claim a responder accepted until a verified event is linked to the assignment. Supabase Realtime publication contains only calls, incidents, voice posts, child alerts and action requests; subscriber SELECT RLS still applies. Raw/private records never enter that publication.

## Signed timeline

`apps/api/src/lib/timeline.ts` canonicalizes finite JSON data without invoking getters/toJSON, and rejects cycles, sparse arrays, symbols, unsupported prototypes and unsafe dictionary keys. Payload, chain and signature use distinct `SAHAJ.timeline.*.v1` domains. Ed25519 signs the chain hash; that hash covers the complete immutable envelope (family/event IDs, sequence, dedupe key, event/entity type, human line, payload hash, prior hash, timestamp, key ID and version). Verifying a complete stream requires a separately trusted head; without one, deletion of the final event cannot be detected. Keep public verification keys for historical key IDs when rotating private signing keys. No private signing key belongs in Git or a browser bundle.

`append_timeline_event(p_event,p_payload_canonical,p_chain_hash,p_signature)` is service-only. Read `timeline_stream_heads`, sign sequence + 1 and its previous hash, then append. On SQLSTATE 40001, reread the head and sign a fresh envelope; retain event ID and dedupe key. A lost response must retry the identical signed request first: duplicate dedupe keys return the original only when all immutable contents and signature match. The database recomputes domain-separated SHA-256 over the canonical payload and fixed scalar envelope, locks the family stream and compares the expected head. Ed25519 verification happens in the application; the SQL signature check is only format validation. Database credentials are trusted and cannot substitute for checking Cedar before signing.

The append routine uses a private, service-executable security-definer implementation so the service role has SELECT only on event/head tables and cannot bypass head serialization with direct DML. Public wrapper is security invoker; no browser role can execute either routine. Owner DML is guarded by the audit immutability trigger. DBA ownership can always alter database objects; this is tamper detection, not a claim of protection against a database owner.

`tests/signed_timeline.sql` rolls back its fixtures and checks Node/PostgreSQL canonical/hash parity, idempotent append, conflicting duplicate, stale head, cross-family head, hash mismatch, direct-write denial and append-only triggers. Test signatures were created with an ephemeral private key that was discarded; only its public key remains. Do not publish timeline content to clients until a separate consent-aware redaction layer exists.
